# Windows: принудительная активация окна мешала проверке сворачивания

## Наблюдавшийся сбой

При проверке подсистемы 03 тест `platform_window_minimize` дважды завершился
ошибкой: в полном прогоне и при отдельном запуске.

```text
The rendering window did not become active.
```

Ошибка возникала внутри `checkRendering()` при ожидании состояния
`focused && !minimized`. Перед ожиданием тест поднимал окно и вызывал
`SetForegroundWindow()` и `SetFocus()`. До чтения пикселей проверка не доходила.
Конкретная причина отказа активации в этих запусках не установлена;
ошибка сама по себе не подтверждает дефект рендеринга или сворачивания движка.

Команда запуска затронутого сценария:

```powershell
ctest --test-dir build/tests-only -R '^platform_window_minimize$' --output-on-failure
```

## Первое изменение (a39888d)

Из `checkRendering()` удалены принудительная активация и ожидание фокуса,
а также использовавшиеся только для этого вспомогательные функции Win32/X11.
Получение foreground-фокуса не является условием проверки сворачивания
или содержимого заднего буфера и зависит от политики оконной системы.
Наблюдавшийся сбой относится к Windows; аналогичный сбой на Linux не подтверждён.

Сохранены автоматические проверки:

- Окно стало видимым и не свёрнуто перед чтением пикселей.
- Задний буфер содержит ожидаемые красный и зелёный цвета.
- Сворачивание и восстановление отражаются в состоянии окна.
- Свёрнутое окно пропускает обмен буферов, после восстановления обмен возобновляется.
- Запрос закрытия обрабатывается и в свёрнутом состоянии.

Отдельные проверки событий фокуса и сброса ввода сохранены. Проверка того,
что оконная система действительно позволяет приложению стать foreground-окном,
оставлена для ручного тестирования.

## Результат первого изменения

После изменения на Windows прошли 40 полных прогонов по 24 теста:
960 запусков без сбоев и пропусков. Это подтверждает результат автоматических
проверок, но не устанавливает причину прежнего отказа активации.

Зависимость теста рендеринга от фокуса устранена. Прежний отказ принудительной
активации отдельно не диагностирован; автоматическое получение foreground-фокуса
не считается проверенным. Linux-ветка изменения пока не запускалась.


## Разделение проверок после сбоя на Linux

На Linux/NVIDIA тест `platform_window` прочитал чёрный пиксель вместо красного
при `focused=0`, `minimized=0` и `GL_NO_ERROR`. Проверка `IsViewable` подтверждает
отображение окна и его родителей, но не отсутствие перекрывающих окон.
Для оконного framebuffer действует pixel ownership test: содержимое перекрытой
области не гарантировано даже при чтении заднего буфера. Сам журнал не доказывает
перекрытие окна, но прежний тест требовал гарантии, которой OpenGL не даёт.

Проверки разделены:

- `platform_rendering` создаёт FBO с RGBA8-текстурой и проверяет красный и зелёный
  цвета через `glReadPixels`. Перед проверкой его собственное окно скрывается:
  пиксели FBO должны оставаться доступны независимо от видимости окна.
- `platform_window`, `platform_window_minimize` и `platform_keyboard` очищают
  оконный задний буфер, проверяют ошибки OpenGL и успешный `present`, а также
  точное число нативных обменов буферов. Чтения пикселей оконного буфера нет.
  Проверки размеров, фокуса, закрытия, сворачивания и восстановления сохранены.
  Во время сворачивания нативных обменов по-прежнему должно быть ноль.

Движок сохраняет требование OpenGL 1.1. Только отдельная проверка цветов требует
OpenGL 3.0, `GL_ARB_framebuffer_object` или `GL_EXT_framebuffer_object`.
Функции загружаются в тесте через WGL/GLX для текущего контекста. Если поддержки
FBO нет, `platform_rendering` возвращает 77 (CTest: Skipped); оконные проверки
продолжают выполняться. Если поддержка заявлена, отсутствие функций,
незавершённый FBO, ошибки OpenGL и неверные цвета считаются сбоем.

Эти автоматические тесты не проверяют итоговую картинку на экране или работу
композитора. Её нужно проверять вручную на Windows и Linux. Результаты прежних
прогонов Windows относятся к прежнему варианту теста и не подтверждают новый.

Спецификация:
[Pixel ownership test](https://wikis.khronos.org/opengl/Default_Framebuffer),
[EXT_framebuffer_object](https://registry.khronos.org/OpenGL/extensions/EXT/EXT_framebuffer_object.txt).

### Проверка нового варианта, 22 октября 2026 года

Linux: сборка `./scripts/test.sh` завершилась без предупреждений. В песочнице
подключение к X11 было недоступно; после запуска CTest вне песочницы прошли
все 29 тестов без пропусков. Четыре сценария `platform_window`,
`platform_window_minimize`, `platform_keyboard` и `platform_rendering`
дополнительно прошли по 20 повторов (80 запусков без сбоев и пропусков).
С ограничением версии и списка расширений Mesa проверен возврат 77:
CTest пометил только `platform_rendering` как Skipped.
Новый вариант на Windows пока не запускался; результат Linux не подтверждает
Windows или исходное окружение Linux/NVIDIA из пользовательского отчёта.
